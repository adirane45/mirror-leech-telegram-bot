## Access Guidelines

### When to Reference Archived Materials

**✅ DO Reference Archive When:**
- Researching how a feature was implemented in previous phases
- Understanding architectural decisions made in Tier 2-3
- Reviewing performance benchmarks from validation reports
- Learning from previous issues documented in change logs
- Reading Tier completion reports for best practices

**❌ AVOID Archive When:**
- Looking for current API documentation (use API_REFERENCE.md)
- Setting up new installations (use INSTALLATION.md)
- Configuring the bot (use CONFIGURATION.md)
- Planning new features (use FEATURE_IMPLEMENTATION_ROADMAP.md)

## Quick Reference: What to Read

### For New Developers
1. Start: `README.md` → `INSTALLATION.md` → `CONFIGURATION.md`
2. Reference: `API_REFERENCE.md` for available classes/methods
3. Archive: Optional - `ARCHIVE/TIER3_TIER3_IMPLEMENTATION_PLAN.md` for full architecture

### For Operations/DevOps
1. Start: `INSTALLATION.md` → `CONFIGURATION.md`
2. Checklist: `DEPLOYMENT_CHECKLIST.md`
3. Archive: `ARCHIVE/reports/DEPLOYMENT_SUMMARY.md` for deployment patterns
4. Archive: `ARCHIVE/TIER3_TIER3_TASK2_MONITORING_REPORT.md` for monitoring setup

### For Future Development
1. Roadmap: `FEATURE_IMPLEMENTATION_ROADMAP.md`
2. Architecture: `AUTOMATION_FEATURES.md` (learn patterns)
3. Archive: Review previous Tier implementations for reference

### For Performance Tuning
1. Baseline: `ARCHIVE/reports/PERFORMANCE_VALIDATION_REPORT.md`
2. Optimization: `ARCHIVE/TIER2_TIER2_DATABASE_OPTIMIZATION.md`
3. Load Testing: `ARCHIVE/TIER3_TIER3_TASK4_LOAD_TESTING_REPORT.md`
